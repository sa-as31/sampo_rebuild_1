# 无人机协同调度系统 UI 风格指南

## 1. 文档目的

本指南用于统一当前系统的视觉语言、布局节奏、组件规范和页面模板，作为后续所有前端页面重构的唯一基准。

本次重构不直接复刻 Anthropic 官网，而是借鉴其以下特征，并将其转译为适合本系统的业务化界面语言：

- 暖白背景与深色文字的高对比基础
- 强标题、强留白、低干扰的信息编排
- 克制的组件装饰与极简的状态表达
- 编辑化内容节奏，而非传统后台式密集堆叠

系统角色和流程保持不变：

- 角色：申请人、管理员、飞手
- 流程：申请 -> 审核 -> 分配 -> 执行 -> 回放

---

## 2. 品牌气质与总体方向

### 2.1 风格关键词

- 克制
- 理性
- 温和
- 可信
- 研究感
- 展示感
- 秩序感

### 2.2 禁止项

- 强发光阴影
- 高饱和大面积按钮
- 重渐变铺满全屏
- 过多边框叠加
- 小卡片密集平铺
- 说明文字过长且到处出现
- 一个页面同时展示过多指标和操作入口

### 2.3 系统总体视觉策略

- 全站以暖白为主背景，不再以深蓝为主背景
- 深色只作为局部功能舞台使用，例如 2D/3D 联合视图、回放画布、特殊数据容器
- 页面优先传达“当前任务是什么”，其次再传达“能做什么”
- 把操作区集中，把信息区分层，不让按钮和指标互相争夺视觉焦点

---

## 3. 设计令牌

### 3.1 颜色系统

#### 基础背景

- `--bg-page`: `#F4F1E8`
  - 全站主背景，偏暖白
- `--bg-section`: `#ECE7DA`
  - 大分区背景，用于 Hero 或大模块承托
- `--bg-card`: `#F8F5EE`
  - 卡片背景
- `--bg-dark-stage`: `#101A26`
  - 深色功能舞台，仅用于联合运行视图、历史回放、3D 视图等高对比区域

#### 文本颜色

- `--text-primary`: `#171717`
  - 主标题、关键数字、主文案
- `--text-secondary`: `#4D4A43`
  - 正文和说明
- `--text-muted`: `#7A746B`
  - 辅助说明、标签、元信息
- `--text-on-dark`: `#F5F2EB`
  - 深色舞台上的文字

#### 边界与分隔

- `--border-soft`: `rgba(23, 23, 23, 0.10)`
- `--border-medium`: `rgba(23, 23, 23, 0.18)`
- `--divider-light`: `rgba(23, 23, 23, 0.08)`

#### 状态色

- `--state-success`: `#2F6B4F`
- `--state-warning`: `#A56A1C`
- `--state-danger`: `#A53D2D`
- `--state-info`: `#365D8D`

说明：

- 状态色仅用于任务状态、告警、审批结果、关键提示
- 任何页面不允许大面积使用状态色作为背景主色

### 3.2 圆角

- 页面大容器：`28px`
- 标准卡片：`24px`
- 输入框 / 按钮：`18px`
- 小标签 / 微按钮：`999px`

### 3.3 阴影

- 卡片主阴影：
  - `0 10px 30px rgba(17, 17, 17, 0.05)`
- 浮层阴影：
  - `0 20px 60px rgba(17, 17, 17, 0.10)`

要求：

- 只允许柔和阴影，不允许强蓝光或发光边缘

### 3.4 间距

- 页面左右安全边距：`48px` 到 `72px`
- Hero 与内容区间距：`48px` 到 `72px`
- 大模块之间：`32px`
- 卡片内部：`24px` 到 `32px`
- 表单字段垂直间距：`20px`

### 3.5 内容宽度

- 主内容最大宽度：`1440px`
- 阅读性强的文字区块：`640px` 到 `760px`
- 任务详情主舞台区：可放宽到 `1600px`

## 4. 字体体系

### 4.1 标题策略

- 中文主标题使用强对比、大字号、较紧字距
- 标题不依赖颜色强调，而依赖字号、断行和留白
- 页面一级标题应当像“页面命题”，不是简单模块名

示例：

- 不推荐：`管理员任务中心`
- 推荐：`审核申请并调度飞手执行`

### 4.2 正文策略

- 正文采用稳定、清晰、无衬线字体
- 单段说明尽量控制在 2 行到 4 行
- 一块区域中只保留一层主说明，不要解释性文字重复出现

### 4.3 字号梯度

- Hero Title：`56px` 到 `72px`
- Section Title：`32px` 到 `40px`
- Card Title：`22px` 到 `28px`
- Key Metric：`40px` 到 `56px`
- Body：`18px`
- Secondary Body：`16px`
- Caption / Label：`13px` 到 `14px`

### 4.4 数字与指标

- 关键数字应单独占据一行或明显区块
- 同一区域只保留 2 到 4 个最重要指标
- 次级指标移入详情层，不要在首页堆满

---

## 5. 布局原则

### 5.1 页面组织方式

每个顶层页面统一采用三段结构：

1. 标题区
2. 关键行动区
3. 内容区

### 5.2 页面节奏

- 第一屏只讲一个中心问题
- 第二屏再给出操作或状态
- 第三层才展示告警、回放、历史、反馈等细节

### 5.3 分栏原则

- 默认优先双栏，不轻易三栏
- 只有在“主舞台 + 侧边信息”场景下，才使用 `2fr / 1fr` 分栏
- 表单页优先单列或 `3:2` 结构，确保阅读和填写自然

### 5.4 卡片原则

- 少卡片，大容器
- 一个卡片只承担一个清晰目的
- 多个相关信息优先合并成一个大模块，而不是拆成很多小块

---

## 6. 交互与动效原则

### 6.1 动效节奏

- 动效时长建议：
  - 微交互：`160ms`
  - 面板切换：`220ms`
  - 详情展开：`260ms`

### 6.2 动效类型

- 淡入淡出
- 轻微位移
- 高度/透明度展开
- 分栏变化时平滑伸展

禁止：

- 弹跳
- 大幅旋转
- 重粒子特效
- 高频闪烁

### 6.3 交互统一性

- 所有 tab 切换使用统一高亮样式
- 所有详情展开使用一致的圆角和位移动画
- 所有按钮 hover 只做轻微明暗变化，不做激进变色

---

## 7. 组件规范

### 7.1 导航栏

- 背景与页面主背景接近，不做明显色块切断
- 左侧为系统名和当前页面命题
- 右侧为身份信息、退出按钮
- 导航切换采用安静的 segmented control

### 7.2 Hero 区

- 一页只能有一个 Hero 区
- 包含：
  - 大标题
  - 一句核心说明
  - 1 到 2 个关键行动按钮
- 不放大量业务卡片

### 7.3 按钮

#### 主按钮

- 用于该区域唯一主动作
- 背景以深色或低饱和信息色为主
- 不同页面同时只保留 1 到 2 个主按钮

#### 次按钮

- 透明或浅底色
- 用于辅助操作，如筛选、展开、切换

#### 文本按钮

- 用于导出、跳转、查看详情等次级动作

### 7.4 表单

- 输入框高度统一
- 标签置于上方
- 占位说明简洁，不写教程式长句
- 日期、地图、任务类型等关键字段优先可视化选择

### 7.5 信息卡片

- 卡片标题清晰
- 说明文字不超过 2 行
- 主数值突出，次信息作为脚注
- 卡片数量过多时优先合并

### 7.6 列表项

- 列表项像“可进入的条目”，不是压缩表格
- 每项至少包含：
  - 主标题
  - 状态标签
  - 一条关键信息行
  - 一条时间或角色信息行

### 7.7 状态标签

- 使用轻底色 + 深色字
- 颜色只表达业务状态，不负责装饰页面

建议映射：

- 待审核：浅琥珀
- 待执行：浅蓝灰
- 执行中：浅蓝
- 已完成：浅绿
- 已驳回 / 失败：浅红

### 7.8 2D / 3D 视图容器

- 外层使用深色舞台，保持运行画面聚焦
- 容器标题、指标和控制栏采用浅色文字
- 视图本体不要被过多边框切割
- 2D 与 3D 保持同一视觉家族，但允许比例不同

## 8. 页面模板

### 8.1 登录页模板

目标：像研究型产品入口，而不是普通后台登录框。

结构：

- 顶部系统名
- 中央大标题
- 一句项目价值说明
- 角色切换控件
- 登录表单

要求：

- 页面中央聚焦
- 不展示过多测试账号列表
- 用文案建立“系统可信度”和“毕业设计完成度”

### 8.2 申请人页面模板

目标：强调“任务申请”而不是“后台操作”。

结构：

- 标题区：本次申请要解决什么任务
- 申请表单区
- 申请预览区
- 历史申请列表

要求：

- 表单是页面主角
- 历史记录放到下方，弱化处理
- 地图、时间、任务类别优先可视化表达

### 8.3 管理员页面模板

目标：从“控制台”转为“审核与调度工作台”。

结构：

- 标题区
- 三个一级工作流 tab：
  - 申请审核
  - 执行中任务
  - 已完成任务
- 当前工作流的主内容区

要求：

- 一次只突出一个工作流
- 列表在左，详情在右，或上概览下详情
- 不在同一屏塞入审批、执行、回放三类重任务

### 8.4 飞手页面模板

目标：弱化后台感，强化“执行任务”的单任务聚焦体验。

结构：

- 左侧任务列表
- 右侧任务详情
- 详情内分三层：
  - 执行
  - 反馈
  - 回放

要求：

- 联合运行视图是主舞台
- 操作按钮集中在视图上方
- 速度、暂停、异常反馈属于同一操作区

### 8.5 运营大屏模板

目标：更像展示页，而不是开发调试页。

结构：

- 页面命题
- 当前任务态势
- 主观测视图
- 少量关键指标

要求：

- 删除多余解释文案
- 指标不超过 4 到 6 个
- 画面优先，数字其次

---

## 9. 现有页面重构映射

### 9.1 当前需保留的业务能力

- 登录认证
- 角色切换
- 任务申请
- 审核与飞手分配
- 飞手执行
- 联合运行视图
- 历史回放
- 告警与反馈

### 9.2 当前需优先弱化的旧设计特征

- 深蓝色大面积铺底
- 信息块碎片化
- 一个页面同时存在过多按钮
- 为解释功能而写的大段说明
- 卡片和边框过密

---

## 10. 实施顺序

后续页面实现必须按以下顺序推进：

1. 登录页
2. 申请人页
3. 管理员页
4. 飞手页
5. 运营大屏

原因：

- 先把视觉入口和整体调性定下来
- 再重构“申请 -> 审核 -> 执行”主链路
- 最后收束到展示型大屏

---

## 11. 开发约束

- 继续沿用当前 Vue 单页架构
- 不引入新的 UI 组件库
- 现有 API 接口、角色模型和任务流转不改
- 2D/3D 画布逻辑保留，只改容器与周边呈现
- 后续页面实现必须优先复用本指南中的颜色、间距、字号和组件规则

---

## 12. 验收标准

当后续页面按本指南实现后，应满足：

- 不看代码也能感受到整站风格统一
- 登录页、申请页、管理员页、飞手页、大屏页属于同一设计系统
- 首屏不再像后台系统，而更像“研究型任务调度产品”
- 信息密度下降，但关键流程效率不下降
- 2D/3D 核心功能保留，且在暖白风格中依然具备视觉聚焦能力
